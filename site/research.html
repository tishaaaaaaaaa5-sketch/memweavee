01 / RESEARCH QUESTION

What should memory preserve?

The central problem is a constrained selection task: preserve useful evidence from a long history before the future question is known, then test whether that evidence can be recovered and used.

Primary research question

Given a conversation history and a strict memory budget, can a query-agnostic selector preserve more future-answerable evidence than strong simple and learned baselines, and does that retention advantage translate into better downstream answer quality across datasets and conversation domains?

Track A · Retention

  • Selector sees history and budget, not the future question.
  • Compare evidence-session recall at matched cost.
  • Measure precision, all-evidence coverage, budget violations, and per-conversation outcomes.

Track B · Memory utilisation

  • Frozen reader receives retained memory plus question.
  • Measure exact match, token F1, grounding, abstention, and unsupported claims.
  • Keep reader, prompt, decoding, and context budget fixed.
Important distinction: evidence recall is not answer accuracy. The original v2.0–v2.3 work explicitly separates query-agnostic retention (Setting B) from question-conditioned retrieval/selection (Setting A). The later role-aware follow-up uses question-similarity features, so it must not be presented as a purely query-agnostic selector.

06 / FAILURE ANALYSIS

MFAR: diagnose the stage before spending more budget

Memory Failure-Aware Retrieval is a proposed lifecycle-aware controller. It should identify where evidence disappears and choose a targeted intervention instead of blindly increasing top-k or memory size.

Failure mode 1

Construction

Relevant source information never becomes a candidate memory item. Potential intervention: source re-ingestion or extraction repair.

Failure mode 2

Compression

Evidence exists before compression but is omitted, distorted, or loses qualifiers/provenance. Potential intervention: revise compression or preserve a source span.

Failure mode 3

Retrieval

Sufficient evidence remains in memory but is not surfaced. Potential intervention: query expansion, reranking, or retrieval budget adjustment.

Failure mode 4

Answering

Sufficient evidence reaches the reader but the answer is unsupported, incomplete, or incorrect. Potential intervention: grounded generation or abstention.

What is actually verified

  • Trace schema, retention adapter, event-validator tests, and an original-data retention audit exist in the repository.
  • The reported retention audit covers 2,115 traces across 235 questions; candidate-pool consistency and evidence provenance passed.
  • All four MFAR failure labels remain NOT_OBSERVABLE in the retention export. No diagnosis probabilities were estimated.
  • A real traced backend run, full construction-to-answer event coverage, lineage validation, and traced-vs-untraced parity are not established by the current release audit.

07 / LIMITATIONS & RESEARCH INTEGRITY

What the evidence does not establish

The site reports positive results and negative findings together. These boundaries are part of the research, not footnotes to hide.

Evaluation limits

  • Stage B, Stage C, v2.3, and final role-aware results are different experimental records; do not average or substitute them.
  • The main role-aware test is one LongMemEval-S split. The project process was iterative, not preregistered.
  • Question-level bootstrap may understate dependence when questions share conversations.
  • LoCoMo and Long-MT-Bench+ reader studies have only 10 and 11 conversation clusters respectively.
  • Token F1 and exact match are lexical metrics, not semantic entailment or factual-grounding audits.

Method and release limits

  • The 10% primary budget in several role-aware reports is a word-count proxy, not exact tokenizer cost.
  • Novelty blends did not improve the DEV result; the tested 50/50 blend materially reduced recall.
  • The v2.3 learned-selector edge over low-novelty was small and sensitivity-dependent.
  • MFAR remains a proposal/partial trace audit, not a validated failure detector.
  • The 2026-11-27 release audit withdrew a ZIP containing cleartext LoCoMo-derived spans. Do not redistribute historical ZIP copies; privacy and license review remains open.
Canonical pipeline freeze is not complete: feature configuration remains unfrozen, the old TEST split has already been inspected, and the next selector must be selected using DEV-only grouped validation. MW-ECS must remain a proposed method until its components are implemented and tested.
